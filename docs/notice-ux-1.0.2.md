# 注意書きの方針 — 1.0.2

v1.0.1ではすべての案内に確認チェックが必要でした。1.0.2では、PDFの出力方針を維持し、実際に失われる情報と分割範囲に基づいて案内します。

| 分類 | 条件 | 画面・実行 |
|---|---|---|
| 案内なし | 維持されるWeb・メールリンク、同じ出力内へのリンク、全ページが残る出力の正常なしおり・移動先、空の内部設定、標準の番号・表示設定 | 通常どおり実行 |
| 軽微な変更 | 別の出力へのページリンク、解決できない移動先、各出力から外れるしおり・名前付き移動先、独自の番号・表示設定や開いたときの移動先の省略 | 短い案内。確認チェック不要。実行ボタンを無効にしない |
| 重要な変更 | 読み上げ構造の実データ、ページ・注釈との構造の対応情報が失われる | 「読み上げ用の構造情報は引き継がれません。」を表示。確認チェックが必要 |
| 非対応 | 暗号化、電子署名、入力フォーム、添付、スクリプト等の既存の拒否条件 | 原因を表示し実行不可。既存の安全制限を維持 |

詳細は「詳しい説明」に折りたたみ、初期状態は閉じます。重要な案内は折りたたみの外に残し、ほかの変更の件数を詳細の見出しに示します。詳細を開くだけでは重要な変更を確認した扱いにはなりません。分割条件が変わった場合は再判定し、確認をリセットします。詳細内は高さを制限してスクロールでき、分割ボタンは画面下部に残ります。

空のStructTreeRoot、Markedだけの宣言、空のしおり・名前・表示設定には実際の情報損失がないため案内を出しません。一方、構造の内容またはStructParent(s)がある場合は、不完全な構造でも重要な案内を残します。標準のアラビア数字（1から連続する既定番号）や既定の表示設定は変更の案内を出しません。それ以外は省略される設定を名指しします。

判定は読み込み時と分割直前の両方で行います。呼び出し側で読み込み時の判定を変更しても、重要な変更の確認を回避できません。ページのコピー・リンクの再配置・しおりの再構築・ファイル保護・後片付けの処理は変更していません。PDFsharp 6.2.4と依存関係、NSISのインストール方針も同じです。

回帰テストは、空の設定、読み上げ構造と対応情報、分割範囲によるリンク・しおり・移動先への影響、解決できない移動先、標準・独自の表示設定、軽微な案内での実行、重要な案内での制限を検証します。既存の署名・暗号化・フォーム拒否、PDFの内容・フォント・画像・サイズ・回転・順序、描画比較、インストーラーの検証も継続します。

実際に問題となったPDFは未提供のため、そのPDFの生成元・内部情報・改善結果は未確認です。Office/Googleドキュメント相当の合成PDFを利用した結果とは区別します。詳しい情報保持方針は [v1.0.1の互換性メモ](pdf-compatibility-1.0.1.md) を参照してください。確認が必要な分類と画面は本書が最新です。
