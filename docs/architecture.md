# Architecture and safety decisions

Core: immutable preview information + SHA-256 input identity, strict split planning, parsed PDF feature inspection, exclusive background processing, same-volume staged publication, no-overwrite output, rollback. WPF: single screen and virtualized preview, busy input lock, async loading and splitting, live status, folder picker, keyboard focus borders, scrolling at smaller screens/DPI. Splash asynchronously overlaps startup and closes in `finally`.

PDFsharp 6.2.4 was checked against the official MIT license and tag source. `PdfPages.ImportExternalPage` retains Resources, Contents, MediaBox, CropBox, Rotate, BleedBox, TrimBox and ArtBox. It does not clone arbitrary page dictionaries, so v1 rejects unrecognized page keys including transparency `/Group` and `/UserUnit`, rather than silently dropping them. Output ColorMode is Undefined to prevent PDFsharp inserting a new transparency group. All indirect/direct dictionaries are inspected through the parser; no naive raw-byte feature matching. Catalog document features that cannot be copied are rejected. PDFsharp can still have compatibility limits; rendered fixture comparison supplements exact decoded content stream, font/image resources and page box tests.

NuGet runtime graph: PDFsharp 6.2.4, Microsoft.Extensions.Logging.Abstractions 8.0.3, Microsoft.Extensions.DependencyInjection.Abstractions 8.0.2 and System.Security.Cryptography.Pkcs 8.0.1. All MIT. No AGPL, network APIs, telemetry, advertisements or automatic update checks. Runtime license material is taken from the exact publish runtime NuGet package. Installer embeds NSIS license notices.

Installer: fixed per-user default path, HKCU metadata, named maintenance guard, semantic version check, generated ownership list, individual deletion, no recursive installed-directory deletion, PDF deletion prohibited. Future upgrades read the previous package's list to remove obsolete binaries. The directory is removed only when empty. Interrupted installation may require rerunning Setup. Downgrade is refused; signing hooks are opt-in and no certificate or fee is needed for the unsigned build.

There is no full transaction across power failure. File publication is atomic per file and catches failures to roll back earlier outputs. PDFsharp parsing/save operations cannot be interrupted mid-call and whole-source loading depends on available RAM. Background workers keep the dispatcher responsive. Windows filesystem and long-path policy still apply; no OS/security policy is changed by this application.
